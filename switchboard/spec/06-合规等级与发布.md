# 06 合规等级与模块发布

- 状态：规范性（Normative）
- 版本：0.1

## 1. 合规等级

| 等级 | 要求 | 权利 |
|---|---|---|
| **L-A 登记** | manifest 完整 + caps 声明 + 遥测必填字段（03 篇）通过自动校验 | 进入注册表，可被 Studio 引用（灰显） |
| **L-B 可用** | 单阶段 trait 完整实现 + T0 剖面跑通 + **负向探针全过**（见下） + 原理卡片机校通过 | 可执行、可组合进 Plan |
| **L-C 认证** | 全计划执行 + T3/T4 实网剖面（均匀+突发双口径）+ `bench.json` + M12 遥测符合度 100% + 复跑验证 | 获综合分、参与推荐排序 |

**负向探针（评审修订 #8：一票否决项的自动化检测，L-B 门槛）**：

| 探针 | 判定 |
|---|---|
| `probe.path_kind` | T4 强制中继剖面下 `path.kind` 必须 = relay |
| `probe.fingerprint` | 指纹错配的 IdentityHello 必须被 close（code 4xxx），且业务数据零字节过信道 |
| `probe.dgram_backpressure` | 灌满发送队列后 `send_dgram` 必须在预算内返回 WouldBlock（阻塞即 fail） |
| `probe.relay_blind` | 中继节点侧抓包，业务负载必须不可读（端到端加密验证） |

一票否决（任何等级）：`path.kind` 谎报；绕过指纹互认；`send_dgram` 阻塞等待；中继可解密业务流量——即上述四探针的运行期版本。

## 2. 模块 manifest（registry/modules/*.json）

```jsonc
{
  "id": "sb.quinn.quic", "version": "0.1.0",
  "stages": ["transport"],
  "binding": "native-rust",
  "provides": { "congestion": ["cubic", "bbr"], "datagram": { "max_size": 1200, "lossy_ok": true },
                 "streams": { "reliable_ordered": true, "bidi": true, "max_concurrent": 1024 },
                 "mtu": 1200, "multipath": false },
  "requires": { "path": ["direct", "relay", "loopback"] },
  "telemetry": "switchboard/telemetry-v1",
  "compliance": "L-B",
  "bench": { "file": "bench/sb.quinn.quic.json", "composite": null },
  "origin": { "adapted_from": "rd crates/rd-transport", "upstream_ref": ["quinn 0.11"] },
  "principles_card": "docs/cards/rd-quic.md",
  "license": "MIT"
}
```

字段 MUST：`id` 全局唯一（`sb.<域>.<名>`）；`stages` 数组（整栈 process 模块如 tailscale 声明 `["discovery","punch","relay","transport"]`，v0.1 执行器按其声明的 stage 单值取用）；`provides` 可被 01 §1 协商（`datagram.max_size` 统一定义为**应用载荷上限**，不含传输封装头）；`telemetry` 声明遥测契约版本。

**原理卡片机校（评审修订 #10）**：注册表加载时校验 `principles_card` 文件存在、包含「对规范的启示」小节、且其声称的上游项目与 `origin.adapted_from` 一致；不过则降级 L-A。

## 3. 注册表（registry/index.json）

- 内容：模块清单 + 每 Profile 推荐组合（如「家宽帮家人」「纯 LAN」「移动 CGNAT」）。
- 排序：L-C 综合分 → L-B → L-A；同分按 recovery_ms（弱网体验优先）。
- 治理：v0.1 由本项目维护；抽离独立仓库后开放 PR 准入（L-C 认证流水线）。

## 4. 原理卡片制度

每个模块 MUST 附**原理卡片**（从上游真实源码提炼，带 文件:行号）：

1. 一句话原理；2. 关键机制（公式/时序/参数）；3. 已知缺陷与教训；4. 对规范的启示（哪些上升为契约、哪些保留为私有实现）。

这是「根据代码理解底层」的制度化：防止模块只是被包装，而其设计智慧被丢进抽象的黑洞。
