## T-036 正式签名密钥轮换与版本基线
- 优先级：**P0（全局卡点）**｜预估：0.5d｜前置：无｜外部依赖：无（决策 + 密钥管理）
- 可并行组：无——T-038/T-041/T-043 均依赖本卡

### 目标
上线前必换的两样密钥之一（路线图 §上线前检查清单）：授权签名种子从仓库内公开开发种子换为正式随机种子；版本基线升 0.3.0。

### 修改范围
- 正式种子：`openssl rand -hex 32` 本地生成 → 更新 `crates/rd-security/src/license.rs` 的 `LICENSE_PUBKEY_HEX`；**私钥入密码管理器，绝不进仓库/git 历史**
- 版本号：workspace 各 Cargo.toml + `apps/rd-controller/src-tauri/tauri.conf.json` + `package.json` 升 0.3.0
- 公告：使用说明/dist 附注「旧开发码失效，联系重发」

### 验收
1. 开发种子签的旧码被拒（验签失败路径有单测）；新种子签发→验签通过。
2. `git grep` 全仓库无正式种子私钥痕迹。

### 风险
已发出的开发码全部失效（当前量≈0，影响可控）。

## T-037 NSIS 安装包打磨（agent + controller）
- 优先级：P1｜预估：1.5d｜前置：无｜外部依赖：无

### 目标
双击安装、开机自启勾选、卸载干净（含信任列表清除确认）——分发底线第 3 条。

### 上下文
- tauri.conf.json bundle targets="all"，NSIS 产物 CI 已能出（dist/ 有 0.1.0 setup.exe），但未做钩子定制
- agent 托盘 HKCU Run 自启已有（`apps/rd-agent/src/tray.rs:516` `set_autostart`，指向当前 exe，免 UAC）——安装版直接复用
- agent 为便携 zip（`scripts/package-agent.ps1`，FFmpeg LGPL DLL 随包）——安装器需继承合规链（DLL + LICENSE 随装）

### 修改范围
- `tauri.conf.json` bundle.nsis：安装模式/语言/目录细化
- NSIS 钩子脚本：安装时「开机自启」勾选项（写 HKCU Run）；卸载时停运行中 rd-agent/rd-controller → 清 HKCU Run + `%APPDATA%\rd`（含 trusted.json 信任列表）**弹确认提示**
- `scripts/package-agent.ps1`：增 NSIS 打包分支（或 Tauri 统一出 agent 安装器）

### 验收
1. 双击装/卸干净；重装后无残留信任项；自启勾选生效（任务管理器启动项可见）。
2. 卸载时运行中的 agent 被正常收场（会话关闭、托盘退出）。

### 风险
卸载钩子误删用户数据——提示文案必须明说「将删除信任设备列表」，文案过审再合。

## T-038 Tauri updater 接入（控制端）
- 优先级：P1｜预估：1.5d｜前置：T-036（密钥规范）｜外部依赖：无

### 目标
自动更新——没有自动更新就没有第二次机会（路线图原话）。

### 修改范围
- `apps/rd-controller/src-tauri`：加 `tauri-plugin-updater`；conf 配 endpoints（先用 GitHub Releases latest URL）+ pubkey 占位
- `tauri signer generate` 出更新密钥对：公钥进 conf，**私钥进密码管理器 + CI secret，不进仓库**
- 前端：启动时静默检查（节流，如 24h）+ 设置页/托盘「检查更新」手动入口；更新提示条（版本号+更新说明+安装按钮）

### 验收
1. 本地双版本模拟升级成功（本地静态服务器托管 v0.2.9 假版本 → 0.3.0 升级走通，签名校验过）。
2. 篡改更新包 → 验签拒绝。

### 风险
公钥一经发版不可更换——生成后立即备份私钥再发版。

## T-040 崩溃上报（两端）
- 优先级：P1｜预估：1.5d｜前置：无｜外部依赖：无（收件端点先用现成免费服务）

### 目标
panic 不静默丢：本地留痕 + 用户可选上传（信任底线：用户点击才传）。

### 修改范围
- `apps/rd-agent` / `apps/rd-controller/src-tauri`：panic hook → `logs/crash/<ts>-<ver>.dump`（元数据：版本/时间/panic 消息/线程/OS；**不含内存转储，避免隐私争议**）
- agent 托盘「上报崩溃…」入口 + 脱敏预览框（用户看到内容再确认）；controller 设置页同款
- 上传通道：GitHub Issue 表单模板或静态收件端点（量 <100/月不需要真后端）

### 验收
1. 人为 panic（测试开关）后本地留 dump 文件；上报走用户确认；隐私政策含对应条款（引 T-042）。

### 风险
无（不传内存转储则风险最低）。

- 优先级：P2｜预估：脚本 1d + 开户等外部｜前置：**T-036**（正式种子）｜外部依赖：**支付渠道开户（面包多/爱发电，实名/费率）**

### 修改范围

### 验收

### 风险

## T-043 多区域中继（Pro 优先通道）
- 优先级：P2｜预估：代码 2d + 部署等外部｜前置：T-041（Pro 码判别已有）｜外部依赖：**香港 VPS + 腾讯云账号 + 域名（国内节点备案风险，README 已提示未备案 443 被拦）**

### 上下文
`switchboard/deploy/derper/` 套件已有（headscale+derper+Caddy compose），但定位「家庭自用、拷到 VPS 手动部署」——商用多区域需产品化。

### 修改范围
- 部署产品化：香港 + 腾讯云两份正式 compose/配置（域名 TLS 自动化、进程守护、监控探针）；derp-map 双 Region
- 客户端：Pro 授权用户自动注入优先 DERP 配置（授权态已可判别）；多 Region 延迟探测择优；Free 用户不受影响（现有 rd-relay/Tailscale 路径不动）
- 中继回退链文档化：打洞直连 → rd-relay → DERP 多区域

### 验收
Pro 码用户中继 RTT 明显优于默认路径；Free 无感；两 Region 各自单点故障不中断服务（择优切换）。

### 风险
备案/运营商拦截（国内节点）；headscale 面向商用需重构配对逻辑——先小规模验证再推广。
