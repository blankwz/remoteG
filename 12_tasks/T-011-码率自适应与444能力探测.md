## 目标
根据 RTT/丢包/发送队列调整码率与帧率；探测本机能否编码 H.264 High 4:4:4，供握手协商。

## 实现步骤
1. `rate.rs`：`RateController`（AIMD）：输入每 200 ms 的 `rtt_ms`、`queued_bytes`（发送队列积压）、`lost_ratio`；积压 > 1 帧或 RTT 比基线上升 > 50% → 码率 ×0.7；否则每 1 s +10%，上下限 `[500, 20000] kbps`；码率低于 1500 kbps 时建议帧率降至 30。
2. `caps.rs`：`probe_encode_caps() -> Vec<Codec>`：始终包含 `H264_420`；尝试用 ffmpeg 硬编以 `pix_fmt=yuv444p`、profile `high444p` 编码 1 帧，成功则加入 `H264_444`。结果缓存。
3. 协商规则函数：`negotiate(enc: &[Codec], dec: &[Codec], dec_444: bool) -> Codec`，优先 `H264_444`（双方都支持），否则 `H264_420`。

## 接口
```rust
pub struct RateInput { pub rtt_ms: u32, pub queued_bytes: usize, pub lost_ratio: f32 }
pub struct RateDecision { pub kbps: u32, pub fps: u32 }
pub struct RateController; impl RateController { pub fn new(start_kbps: u32, max_fps: u32) -> Self; pub fn update(&mut self, i: RateInput) -> RateDecision; }
pub fn probe_encode_caps() -> Vec<rd_proto::v0::Codec>;
pub fn negotiate(enc: &[rd_proto::v0::Codec], dec: &[rd_proto::v0::Codec], dec_444: bool) -> rd_proto::v0::Codec;
```
