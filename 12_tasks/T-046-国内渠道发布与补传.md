## 目标
国内用户下载/更新不被 GitHub 卡死：CI 发布时自动把产物镜像到腾讯云 COS（CDN 回源），手动补传可中断重跑不重复劳动。密钥纪律：只记名称不存密钥——CI 走 secret，本地走 `@文件` 引用，绝不进仓库/日志/命令行参数。

## 修改范围（已完成）
- `crates/rd-update-pack/src/mirror.rs`（`mirror` feature 门控，agent 依赖不引入 reqwest/clap/hmac）：
  - COS XML API 签名：KeyTime→SignKey→HttpString→StringToSign→Signature 全链，UrlEncode RFC3986 保留字全集，官方固定向量单测锚定
  - CosClient（blocking reqwest，rustls，600s 超时）：put/head/get
  - 内容寻址：上传前 head 对比 sha256——相同跳过（可中断重跑不重传）、存在但不同拒绝（防覆盖不同内容）
  - 对象布局：`v{version}/{zip,pack,update.json,sig}`（历史存档）+ `latest/{update.json,update.json.sig,pack}`（渠道指针）；pack 传双份（latest 供 Agent 下载、v 目录存档）
  - 防回滚：latest 指针只在新版本 > 当前时切换（`should_switch_pointer`，单测锚定）
- `crates/rd-update-pack/src/bin/rd-pack-cli.rs`：mirror 子命令（`--tag`、`--cos`/`--cos_keys` 支持 JSON 或 `@文件`）
- `scripts/rd-mirror.ps1`：密钥 env（`RD_COS_CONFIG`/`RD_COS_KEYS`）或参数落临时文件，finally 删除临时目录
- `.github/workflows/release.yml`：mirror-cos job（needs publish；secrets 缺时明确跳过）

## 验收标准

## 风险与备注
- 无 COS 密钥，mirror 全链路未真实跑过——签名算法用官方固定向量锚定（secretKey=AKIDexample 官方示例算例逐字节对上），风险可控但不等于真渠道验证
- Agent 端 `RD_UPDATE_ENDPOINT` 统一指 `latest/`（三类文件同 base 可取），GitHub Releases 与 COS 布局同构（平铺 base），双渠道无分支
