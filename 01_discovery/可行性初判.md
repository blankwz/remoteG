# 可行性初判
- 状态：已确认
- 说明：澄清前的技术可行性判断，回答“能不能做到”。正式需求分析在澄清后写入 `需求分析.md`。

## 摘要
三项都能做到，难度递增：**窗口捕获（成熟 API）< 文字清晰自适应（编码+分辨率策略）< 结构化自绘（只对部分程序可行）**。
推荐架构：**三级渲染管线**，按窗口能力自动选择，失败自动回退到像素流。

| 级别 | 方式 | 适用 | 文字清晰度 | 带宽 |
|---|---|---|---|---|
| L0 像素 | 窗口视频流 | 所有窗口 | 取决于编码策略（见 §2） | 高 |
| L1 混合 | 视频底图 + 控制端本地渲染文字层（来自无障碍 API） | 暴露 UIA/AX 的原生程序 | 中-高 | 高 |
| L2 语义 | 传结构，控制端完全自绘 | 终端、浏览器/Electron | 原生级 | 极低 |

## 1. 窗口级捕获与操控 —— 可行（成熟）
| 被控端 | 捕获 API | 备注 |
|---|---|---|
| Windows 10 1903+ | Windows.Graphics.Capture（按 HWND，GPU 纹理） | 被遮挡窗口可捕获；最小化不可；有黄色边框（Win11 可关闭 `IsBorderRequired`） |
| macOS 12.3+ | ScreenCaptureKit `SCContentFilter(desktopIndependentWindow:)` | 需屏幕录制授权 |
| Linux X11 | XComposite | 可行 |
| Linux Wayland | xdg-desktop-portal ScreenCast + PipeWire（用户选窗口） | 无法静默选窗口，每次需用户授权 |

难点与对策：
- **弹出菜单/对话框是独立窗口**：按同进程 + Owner 关系跟踪窗口组，合成或作为子流下发。
- **后台窗口输入**：`SendInput` 只作用于前台窗口；`PostMessage` 对部分程序（游戏、Chromium 部分控件）无效。MVP 策略：操作时把目标窗口置前（`SetForegroundWindow` + 限制条件处理）。
- **坐标映射**：窗口客户区坐标 × DPI 缩放；窗口移动/缩放时实时更新。
- **UAC/安全桌面、登录界面**：窗口模式不覆盖，需整屏模式 + 系统服务（参考 RustDesk）。

## 2. 控制端自适应 + 看清字 —— 可行（核心是三招）
文字糊的根因：① 缩放（远端分辨率≠本地视口）；② 4:2:0 色度抽样把彩色/ClearType 字边缘抹掉；③ 低码率量化。
1. **反向适配窗口尺寸（窗口模式独有优势）**：把远端窗口 resize 到「控制端视口 ÷ 远端 DPI 比例」，实现 **1:1 像素、零缩放**。整屏方案做不到这点。
2. **可选调整 DPI**：控制端是高分屏时，请求远端窗口按更高 DPI 渲染（Per-Monitor DPI 程序有效；或用虚拟显示器 IddCx 驱动设定匹配分辨率，参考 RustDesk 虚拟显示器）。
3. **文字友好编码**：
   - 4:4:4 色度（H.264 High 4:4:4 / HEVC RExt / AV1 4:4:4；硬件支持需探测，否则软编）。
   - 静止后**无损精修**（idle N ms 后对脏区发无损帧/PNG 瓦片）。
   - 屏幕内容编码工具（AV1 palette / IntraBC，HEVC SCC）。
   - 脏区 + ROI：文字区域分配更多码率。
   - 控制端禁用双线性模糊缩放；需缩放时用锐化/整数倍缩放。

## 3. 结构化自绘 —— 部分可行
| 程序类型 | 获取结构的方式 | 控制端渲染 | 可行性 |
|---|---|---|---|
| 终端（我方启动的 shell） | ConPTY / pty 直接拿 VT 字节流 | xterm.js 或自研网格渲染，本地字体字号 | **高**（ttyd/tmux 已验证） |
| 终端（已存在窗口） | tmux/screen attach；Windows Terminal 通过 UIA TextPattern 读缓冲区；conhost 用 `ReadConsoleOutput` | 同上 | 中 |
| Chrome/Edge/Electron | CDP（`--remote-debugging-port`）：DOM 快照 + 增量 Mutation + 计算样式 / 资源；类 rrweb 镜像 | 控制端 WebView 重放，可按本地视口重排 | 中（需目标以调试端口启动或装扩展） |
| 内网 Web 应用 | 直接端口转发，控制端本地浏览器打开同一 URL | 原生浏览器 | **高且最简单**（但会话状态不共享） |
| 原生程序（Win32/WPF/Qt） | UI Automation / macOS AX / AT-SPI：控件树、文本、边界框 | L1 混合：视频底 + 本地清晰文字覆盖 | 中-低（还原度有限） |

关键风险：
- DOM 镜像的跨域资源、Canvas/WebGL/视频内容无法结构化 → 这些元素内嵌像素子流。
- 输入回放：L2 下点击需映射回远端坐标或 DOM 节点，焦点/IME 处理复杂。
- 安全：开放 CDP 端口等于完全控制浏览器，必须仅本地回环 + 代理端鉴权。
