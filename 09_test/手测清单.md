## 一、Phase 1 单机功能（15 项，约 40 分钟）

### 1.1 被控端在跑
- **操作**：看右下角托盘，灰色 rd 图标 → 右键点它
- **应看到**：菜单里有「生成配对码 / 已连接：0 / 暂停共享 / 开机自启 / 信任设备 / 打开日志目录 / 授权… / 退出」
- **出问题贴什么**：托盘截图

### 1.2 控制端连上被控端
- **操作**：控制端窗口 → 点「添加设备」→ 地址填托盘「生成配对码」弹窗里显示的地址（形如 `192.168.x.x:21118`）→ 配对码填弹窗里的 6 位数字 → 确认
- **应看到**：设备卡片出现且显示在线（也可以点「扫描局域网」自动发现，更省事）
- **出问题贴什么**：控制端截图 + 托盘弹窗截图

### 1.3 打开测试窗口
- **操作**：在程序文件夹的地址栏输入 `cmd` 回车 → 在黑窗口里输入：
  ```
  clarity-bench.exe testwin --mode clock
  ```
- **应看到**：出现一个 800×600 的测试窗口（带时钟和彩色图案），标题含 clarity-bench
- **出问题贴什么**：黑窗口里的报错文字

### 1.4 看到远程画面
- **操作**：控制端 → 点设备卡片 → 出现「窗口列表」→ 点 clarity-bench 窗口打开
- **应看到**：1~3 秒内出现远程画面，时钟在走，图案清晰无花屏
- **出问题贴什么**：控制端截图 + `%LOCALAPPDATA%\rd\logs` 文件夹里最新日志的最后 20 行

### 1.5 静止区域精修（瓦片）
- **操作**：画面不动 5 秒，然后快速晃动鼠标
- **应看到**：静止的文字/图案在晃动后变得更清晰（高清瓦片叠加），全程无闪黑
- **出问题贴什么**：前后两张截图对比

### 1.6 鼠标点击（本机自测 = 穿透模式）
- **操作**：把控制端窗口**缩小放到屏幕一侧**（能看到测试窗口在旁边）→ 在远程画面里点击测试窗口的位置
- **应看到**：真实的测试窗口**弹到前台**并被真实点击（点击计数增加）；点控制端窗口切回来继续操作
- **说明**：本机自测是「穿透」——点击直达真实窗口，所以它会弹到前面来。双机连接时没有这个切换，鼠标直接控制远端
- **出问题贴什么**：点击前后的截图

### 1.7 键盘输入（穿透模式）
- **操作**：按 1.6 点击一次远程画面（真实窗口已在前台）→ 直接打字，或点工具栏「常用语」发送
- **应看到**：文字出现在真实测试窗口里（它在前台，物理键盘直打也生效）
- **出问题贴什么**：描述现象 + 最新日志尾部

### 1.8 终端
- **操作**：控制端会话页 → 点顶部「+ 终端」
- **应看到**：出现一个能用的命令行，输入 `echo hello` 回车能出 `hello`
- **出问题贴什么**：终端页截图

### 1.9 剪贴板
- **操作**：在本机复制一段文字（Ctrl+C）→ 会话画面**下方**找到会话工具条，点「把控制端剪贴板文本发送到远端」→ 在远程终端里按 Ctrl+V
- **应看到**：粘贴出的是刚才复制的文字；反向点「取回远端剪贴板文本到控制端」也能拿到
- **出问题贴什么**：描述哪一步没生效

### 1.10 悬浮工具栏（画质/常用语/虚拟按键/截屏/只看/剪贴板/信息）
- **操作**：远程画面顶部找到悬浮工具栏（2026-10-27 版新增 👁 只看、📤📥 剪贴板、ℹ 信息按钮）：
  - 画质选「流畅」→ **有绿色提示气泡**，画面在运动时略微变糊；选「高清」变清晰
  - 点 📋 常用语 → 点「你好」→ 远程应出现这两个字
  - 点 ⌨ 虚拟按键 → 点 Enter → 远程有回车效果
  - 点 📸 截屏 → 提示「已保存」，下载文件夹出现 PNG
  - 点 👁 → 提示「已开启只看不控」，此时点画面远程无反应；再点恢复
  - 点 📤/📥 → 提示成功或失败原因（本机先复制一段文字再点 📤）
  - 点 ℹ → 画面右上角显示延迟/码率信息
- **应看到**：以上全部生效，**每次点击都有提示气泡**（没气泡 = 点击没生效，直接截图给我）
- **出问题贴什么**：哪一步没反应的截图 + 说的期望

### 1.11 隐私屏（授权已由 AI 代办放置，直接测）

- **应看到**：被控端屏幕变黑（有提示后），控制端画面照常能看能操作；再点 ⬛ 恢复；**关掉控制端窗口后黑屏自动消失**

### 1.12 录屏
- **操作**：工具栏点 ⏺ → 操作几下画面 → 再点 ⏺
- **应看到**：提示「录制已保存」，下载文件夹出现 .webm 视频且能播放
- **出问题贴什么**：提示气泡截图

### 1.14 文件传输（2026-10-31 新增）
- **操作**：连接会话 → 悬浮工具栏点「更多」→ 点「文件传输」→ 在浮层里点「发送文件到远端…」选一个小文件 → 点浮层里列表中的「Documents」进入，再点一个文件拉取
- **应看到**：发送完成后，被控电脑的「下载\rd接收」文件夹出现该文件且能打开；拉取完成后，本机下载文件夹出现远端文件（重名会变成「名字 (1).后缀」）；传输条目显示绿色完成进度

### 1.15 远程开机 WOL（2026-10-31 新增；可选，需两台电脑）
- **操作**：对一台**连接成功过至少一次**的设备，先正常关机 → 控制端设备页 → 该设备卡片右下「⋯」→ 点「远程开机」
- **应看到**：提示「已发唤醒包」；同网段时几十秒内被控电脑自己开机（BIOS 需开启「网络唤醒 Wake-on-LAN」，多数主板默认开）；没有「远程开机」选项 = 还没连接过（没采集到 MAC）
- **出问题贴什么**：提示气泡截图 + 主板型号（网络唤醒常见被 BIOS/网卡驱动关闭）

### 1.16 EasyTier 组网连接（2026-11-07 新增；需两台电脑 + EasyTier 二进制）

前置：两台电脑各装 EasyTier（官方 release 或源码 build），rd 两端设置页「EasyTier 组网」填同一网络名+密钥+easytier-core 路径，重启 rd。

1. **免管理员模式（默认）**：控制端配转发规则（对端虚拟IP:21118@21130），rd 控制端添加设备时地址照常填直连地址——直连失败应自动快试 `127.0.0.1:21130` 经 mesh 连上（日志含「EasyTier 转发地址连接成功」）。
2. **TUN 模式（管理员）**：被控端配置静态虚拟 IP 后，控制端设备地址直接填对端虚拟 IP（如 `10.126.126.3:21118`）直连；或被控端配置了中继时，虚拟 IP 自动进直连候选竞速（日志含「EasyTier 虚拟 IP 纳入直连候选」）。
3. **降级验证**：easytier-core 路径填错/节点起不来——rd 直连与中继路径完全不受影响（仅日志告警）。

## 五、V0.3 snug 改造手测（2026-11-19 新增）

对应 snug 改造项 A（Agent 自更新 + 国内渠道）、E（窗口还原/静默/恢复/挂死探针）。除 5.4 需 COS 密钥外全部单机可测，统一用 **debug 构建的 rd-agent**（内置公钥是占位、任何签名都拒绝；测试公钥只能注入 debug 构建——这是刻意的 fail-closed，正式渠道归 T-039）。

### 5.1 Agent 自更新全链路（本地 HTTP 模拟发布端，约 20 分钟）

前置准备（一次性）：

1. 生成测试签名密钥对（seed 只放 %TEMP%，别提交）：
```cmd
cargo run -p rd-update-pack --features mirror --bin rd-pack-cli -- keygen --out "%TEMP%\rd-test-sign.key"
```
   stdout 打印的 pubkey hex 记下来。
2. 建独立安装目录 `C:\rd-update-test\`：拷入 `target\debug\rd-agent.exe` 和 `apps\rd-controller\src-tauri\ffmpeg-bin\` 里的全部 DLL，再放一份旧版 zip（chunked 模式找本机 zip 用，名字形如 `rd-agent-0.3.0-win64.zip`）。
3. 出「假新版」发布目录（版本号写 9.9.9，清单版本与本机比较用）：
```cmd
cargo build -p rd-agent --release
scripts\package-agent.ps1
cargo run -p rd-update-pack --features mirror --bin rd-pack-cli -- pack --zip dist\rd-agent-0.3.0-win64.zip --version 9.9.9 --out-dir dist\fake-release --sign-key @%TEMP%\rd-test-sign.key
```
   `dist\fake-release\` 应有 pack、update.json、update.json.sig 三件。
4. 起本地发布服务（窗口别关）：
```cmd
cd dist\fake-release && python -m http.server 8090
```

测试步骤：

5. 启动旧 Agent（新开 cmd，pubkey 换成第 1 步打印的）：
```cmd
set RD_UPDATE_ENDPOINT=http://127.0.0.1:8090
set RD_UPDATE_SIGN_PUBKEY=<pubkey hex>
set RD_UPDATE_MODE=chunked
C:\rd-update-test\rd-agent.exe
```
6. 托盘右键 →「检查更新」→ 应弹「发现新版本 9.9.9」→ 确认 → 被控端日志出现「开始下载更新包」（chunked + 目录里有旧 zip 时，下载字节数应明显小于全包）→ 完成后弹重启确认 → 确认。
7. 重启后：`C:\rd-update-test\rd-agent.exe` 已被对调成 release 版（无控制台、托盘在、功能正常），目录里**无 `*.old` 残留**（新进程启动清理）。
8. 防回滚：再次「检查更新」→ 日志「无可用更新」（9.9.9 不大于 9.9.9）；把发布目录换成 `--version 8.8.8` 重出再查 → 同样拒绝。

### 5.2 坏块注入 / 中断重试 / 只读回退（约 10 分钟）

1. **坏块**：把 fake-release 的 pack 文件随便改 1 个字节 → 重走 5.1 第 6 步 → 应报「下载段解块校验失败」类明确错误，进程不崩、原功能不受影响。
2. **中断重试**：下载确认后、重启前直接杀掉 rd-agent 进程 → 重新启动再「检查更新」→ 应能完整重来（暂存目录残留自动清理）。
3. **只读回退**：`icacls C:\rd-update-test /deny "%USERNAME%:(W)"` 后再「检查更新」→ 应报「安装目录不可写」并在下载前就失败（不半途写坏）；恢复：`icacls C:\rd-update-test /remove:d "%USERNAME%"`。

### 5.3 full 模式对照（约 5 分钟）

`RD_UPDATE_MODE` 不设（默认 full）重走 5.1 → 日志「开始下载更新包」ranges=1、bytes=全包大小，升级同样成功。这是灰度起点通道，与 chunked 走同一拼装链路。

### 5.4 rd-mirror 手动补传（需 COS 密钥，T-039 前跳过）

前置：COS 桶已建；`%USERPROFILE%\.rd-secrets\` 备好 `cos-config.json`（`{"host":"…","prefix":"…"}`）与 `cos-keys.json`（`{"secret_id":…,"secret_key":…}`）——只放本机，绝不进仓库。

```powershell
powershell -File scripts\rd-mirror.ps1 -Tag v0.3.0 -CosConfigPath "%USERPROFILE%\.rd-secrets\cos-config.json" -CosKeysPath "%USERPROFILE%\.rd-secrets\cos-keys.json"
```

应看到：GitHub 产物逐个校验 → 同 sha256 跳过不重传 → latest 三件套上传 → 指针切换；**同 tag 旧版本内容重跑应被拒**（防回滚）。COS 侧抽查 `latest/update.json` 与 GitHub Release 上的一致。

### 5.5 隐私屏重启恢复（改造项 E3，约 5 分钟）

1. 开隐私屏 → 确认黑窗生效。
2. 任务管理器杀掉 rd-agent.exe（模拟崩溃）→ 重新启动 → **黑窗应自动恢复**（被控端日志有隐私屏状态恢复记录）。
3. 关闭隐私屏 → 重启 rd-agent → 不应出现黑窗（关闭状态同样持久化）。

### 5.6 挂死窗口不拖会话（改造项 E4，约 10 分钟）

1. 远程会话中对被控端某窗口做 1:1 适配（走 fit 路径）。
2. 被控端：任务管理器 → 详细信息 → 该窗口所属进程 → 右键「**挂起**」（Suspend）。
3. 再远程触发该窗口适配/或结束会话触发布局恢复 → 操作应在约 1 秒内失败返回（被控端日志含「窗口无响应」），**会话视频不卡死**——这就是探针的意义：挂死窗口的 SetWindowPos 会同步阻塞，没有探针会把整条会话拖死。
4. 右键「继续」（Resume）该进程 → 操作恢复可用。

### 5.7 窗口布局崩溃还原（改造项 E1，约 10 分钟）

1. 记事本摆到一个记得住的位置（如右下角小窗）。
2. 远程会话打开该窗口（触发布局快照记账）→ 会话中把窗口挪大挪位。
3. 任务管理器杀掉 rd-agent.exe（模拟崩溃，正常恢复路径没走）。
4. 重新启动 rd-agent → 记事本应被放回**会话开始前**的位置（日志含「已按账本恢复未复原的窗口布局」）。
5. 正常路径对照：再来一轮但正常断开会话（不杀进程）→ 再杀再启 → 记事本**不应**被挪动（已销账，无事可还原）。

### 5.8 自扰静默（改造项 E2，顺带观察）

开关隐私屏的瞬间，控制端窗口列表不应闪现「黑罩窗口被当成普通窗口列出」之类的短暂错误状态（静默期内事件被过滤，列表稍后刷新为准）。本条弱验证，逻辑正确性主要靠单测锚定。

### 5.9 触屏手势（改造项 C 接线，2026-11-19 新增；需触屏设备——触屏笔记本/平板模式即可）

前置：控制端跑在有触屏的 Windows（WebView2 把触屏 pointer 事件给前端）；远程会话打开一个可滚动窗口（网页/文档）。

1. **轻点=点击**：手指轻点远程画面某处 → 远端在该处产生一次左键点击（按钮/链接正常响应）。
2. **拖动=滚动（带惯性）**：手指快速上滑离开 → 远程窗口内容平滑滚动并**继续惯性滑行一段后自然停止**（控制端 60fps 惯性帧，Chrome 观感近似 1:1）；滑动中途手指按住画面 → 惯性立刻停住（再松手不补发点击）。
3. **长按=右键**：手指按住不动约 0.5 秒后松开 → 远端在按下位置弹出右键菜单。
4. **按住拖动=选择**：按住不动 0.5 秒（不松）再拖 → 远端进入选择/拖拽状态（补发左键按下跟随移动）。
5. **鼠标不受影响**：接鼠标操作画面，行为与改造前完全一致（pointerType 路由隔离）。
6. **只看不控**：对只看不控窗口做手势 → 远端无任何反应（Agent 侧守卫丢弃）。

出问题贴：控制端日志 + 被控端 `%LOCALAPPDATA%\rd\logs` 尾部（含「丢弃连续滚动」类行说明守卫路径）。
