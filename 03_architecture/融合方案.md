# 融合方案：rd 单应用（被控 + 控制一体）

状态：**设计完成，待确认开工**（2026-10-23，用户立项）
目标形态：**一个安装包、一个 exe、一个窗口、一个身份**——装一次即双向：既能被远程，也能远程别人（向日葵模式）。

## 1. 目标与非目标

**目标**
1. 单 exe（Tauri 壳 = 控制端 UI + 被控核心），托盘常驻，开机自启
2. 自绘无边框主窗口（最小化/最大化/关闭，拖拽区）
3. 单身份：同一证书既作为被控身份（别人信任它）也作为控制身份（它信任别人）
4. 安装包顺手写入 Windows 防火墙放行规则（根治跨机 timeout 的首日坑）
5. 兼容迁移：存量配对关系可导入（可选步骤，不做则重配对）

**非目标（本期）**
- 多窗口/多会话并行（维持单会话）
- rd-agent.exe 独立被控形态的 UI（bin 保留作无头/测试模式，不再演进 UI）
- 服务化/UAC 接管（仍列 M2 决策点）
- 移动端（M2）

## 2. 关键决策

| # | 决策 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|---|
| K1 | 进程模型 | **agent lib 化，Tauri 壳同进程内嵌** | 真"一个 exe"；身份/信任存储天然共享；无 IPC 复杂度 | Tauri spawn agent.exe 子进程（假融合，两份身份） |
| K2 | 托盘 | **Tauri 2 tray API 重写**（菜单/状态/配对码） | tray-icon 与 Tauri 同源（muda），移植直接；agent lib 变无头核心，不再管 UI | 保留 agent 自绘托盘（双托盘冲突） |
| K3 | 身份 | **融合版新身份目录 `%APPDATA%\rd\app\`**，首启向导可选导入旧 agent 身份（保留配对） | 干净起步 + 向后兼容两手抓 | 强制重配对（伤用户）；自动合并两套信任表（语义混乱） |
| K4 | 窗口 | Tauri `decorations: false` + `data-tauri-drag-region` + 自绘三按钮（invoke window API） | 单窗口模型，改动集中在前端壳层 | 多窗口（复杂度不成比例） |
| K5 | 防火墙 | **NSIS 安装脚本写入入站规则**（rd-app.exe，UDP） | 安装时一次提权名正言顺；根治首日 timeout | 运行时 UAC 提权（吓小白） |
| K6 | 崩溃隔离 | 放弃（同进程）——agent 代码审计 panic 点（unwrap/expect 已规范）+ panic hook 写日志 | 个人工具，收益不抵复杂度 | 子进程隔离（违背 K1） |
| K7 | 单实例 | 单实例锁（端口 21118 bind 失败=已有实例，托盘提示） | 防双开打架 | — |

## 3. 架构（融合后）

```
rd-app.exe（Tauri 2）
├─ 前端（React）：设备页 / 窗口列表 / 会话 / 设置（新增：被控开关、自启、导入身份）
├─ src-tauri（Rust 主进程）
│  ├─ agent_core（= rd-agent lib 化产物）：QUIC 监听 / 配对 / 窗口管线 / 输入 / 终端 / 发现应答
│  ├─ 现有 controller 逻辑：ConnManager / 命令集 / 剪贴板 / 发现扫描
│  ├─ tray（Tauri tray API）：配对码 / 已连接 / 断开 / 暂停 / 自启 / 信任设备 / 退出
│  └─ window（自绘标题栏事件 + 最小化最大化关闭）
└─ 单身份：identity.bin + trusted.json（双向语义：既是"信任我的"也是"我信任的"）
```

- **rd-agent 仓库形态**：`apps/rd-agent` 拆 `lib.rs`（agent_core：server/session/window_session/input/term/discover/power/clipboard/host_activity 全部 pub 化，`AgentHandle::start(config, events) -> stop`）+ `main.rs`（薄 CLI：run/spike 保留无头模式）。
- **UI 语义调整**：「设备」列表在融合版里是"我能控制的设备"；被控侧视角（谁连过我）进**设置-被控**页（信任管理已在此前托盘菜单，迁移到 UI 页）。
- **协议零变更**：融合不改 rd.proto；身份合并后双方本来就以指纹互认。

## 4. 任务拆解（建议 7 卡，串行为主）

| 卡 | 内容 | 依赖 |
|---|---|---|
| F-1 | rd-agent lib 化：模块 pub 化、`AgentHandle` 生命周期 API、托盘代码剥离、bin 保留无头模式 | — |
| F-2 | src-tauri 集成：启动/停止 agent_core、与 Tauri runtime 共存、单实例锁 | F-1 |
| F-3 | Tauri tray 移植：六项菜单 + 状态每秒刷新 + 配对码（MessageBox→前端 dialog） | F-2 |

| F-5 | 身份迁移：新目录 + 首启导入向导（选旧 `%APPDATA%\rd\data` 身份） | F-2 |
| F-6 | NSIS 防火墙规则 + 产物改名 rd-app + 版本号统一 | F-2 |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| agent tokio runtime 与 Tauri 冲突 | agent lib 接受外部 Handle（Tauri 的 async runtime），不自建 |
| tray 状态同步移植遗漏（六项菜单行为回归） | F-3 验收清单逐项对拍现 tray.rs 行为 |
| WGC/注入在融合进程内的会话边界行为差异 | F-7 跨机矩阵覆盖锁屏/UAC/本机优先 |
| 双身份迁移语义混乱 | K3：只导入不合并，向导一步说清 |
| 旧 rd-agent.exe 用户并存 | 单实例锁 + 文档声明（同机只跑一个被控核心） |

## 6. 工作量预估

F-1～F-7 串行约 **2~3 天**（含回归）。最大不确定点在 F-2（runtime 共存）与 F-3（托盘行为对拍），先行预研可消解。
