# 架构方案
- 状态：已确认

## 摘要
- 被控端 `rd-agent`：Rust 用户态进程，WGC 抓窗 → D3D11 → H.264 编码（硬编优先，OpenH264 兜底）+ 无损瓦片精修 → QUIC（quinn）。
- 控制端 `rd-controller`：Tauri 2（Rust 后端负责网络/会话，前端 TS 负责渲染：WebCodecs 解码视频画到 canvas、xterm.js 终端）。同一套代码 M2 编译 iOS。
- 网络：Tailscale 提供寻址（MagicDNS）、NAT 穿透与 DERP 中继；应用层 QUIC + 证书指纹钉扎做设备鉴权。
- 三级渲染：L2 语义（终端/Web）> L1 混合（UIA 文字层）> L0 像素，按窗口能力自动选择。

## 3. 关键流程
### 3.1 1:1 适配（US-03）
1. 控制端上报视口：`ViewportInfo{css_w, css_h, device_pixel_ratio}`。
2. Agent 计算目标物理尺寸 = `css × dpr`，再按远端窗口 DPI（`GetDpiForWindow`）换算，`SetWindowPos` 调整外框使**客户区**等于目标尺寸。
3. 记录原始 `WINDOWPLACEMENT`，会话结束/切换模式时恢复。
4. 窗口不可调（固定大小/最小尺寸限制）→ 退化：控制端整数倍或 Lanczos 锐化缩放，并提示。
5. 模式：`Fit`（调远端窗口，默认）/ `Scale`（不动远端，本地缩放）/ `Native`（1:1 可滚动）。

### 3.2 编码策略（文字清晰核心）
- 运动帧：H.264 4:2:0（硬件兼容最好），码率自适应（基于 QUIC RTT/丢包）。
- 静止精修：脏区跟踪（WGC 帧 dirty rect，Win11 22H2+ 支持；否则 64×64 块比对）；区域静止 ≥ 300 ms 后发送 **QOI/zstd 无损瓦片**，控制端在视频层之上覆盖，下一次该区域变化时移除。
- 增强（可选）：探测硬件 H.264 High 4:4:4 / HEVC RExt，且控制端 WebCodecs `isConfigSupported` 通过时启用 4:4:4。

### 3.3 窗口组（US-04）
- 以目标 HWND 为根，收集同 PID 且 `GW_OWNER` 链指向根的可见窗口 + 菜单类（`#32768`）。
- 方案：每个子窗口独立 WGC 流，控制端按相对坐标合成（M1）；坐标以根窗口客户区为原点。

### 3.4 输入
- 鼠标：控制端坐标 → 根窗口客户区坐标 → 屏幕坐标 → `SendInput`（`MOUSEEVENTF_ABSOLUTE|VIRTUALDESK`）。
- 首次输入或焦点不在目标时 `SetForegroundWindow`（配合 `AllowSetForegroundWindow`/模拟 Alt 绕过前台锁）。
- 键盘：扫描码透传；文本输入（IME 结果、移动端软键盘）用 `KEYEVENTF_UNICODE`。

### 3.5 终端模式（US-05）
- Agent 用 ConPTY 启动 `pwsh.exe`/`cmd.exe`/`wsl.exe`（可配置），原始 VT 字节流经 QUIC 流传输；控制端 xterm.js 渲染；resize 通过 `ResizePseudoConsole`。
- 会话独立于窗口，控制端断开后保留 10 分钟可重连（环形缓冲 1 MB 回放）。

## 4. 技术选型与替代
| 领域 | 选择 | 理由 | 替代 |
|---|---|---|---|
| 语言 | Rust | 性能、跨平台、生态（windows-rs、quinn） | C++（开发慢）、Go（Win 图形 API 绑定弱） |
| 控制端 UI | Tauri 2 | 一套代码覆盖 Win/mac/iOS；xterm.js、DOM 回放天然需要 WebView | Flutter（RustDesk 方案，DOM 回放难）；原生 wgpu+egui（视频最优但终端/DOM 要重写） |
| 传输 | QUIC (quinn) | 多路流无队头阻塞、内置 TLS1.3、支持 datagram | WebRTC（重、iOS WebView 外难嵌）、TCP+TLS |
| 视频解码 | WebCodecs（WebView2 / WKWebView） | 硬解、零拷贝到 canvas | Rust 侧 dav1d/VideoToolbox 解码后传 RGBA（带宽大） |
| 编码 | ffmpeg 硬编（h264_nvenc/qsv/amf/mf）+ OpenH264 兜底 | 覆盖面广 | 直接调 MF Transform（代码量大） |
| 无损瓦片 | QOI + zstd | 编解码快、实现简单 | PNG（慢）、WebP lossless |
| 网络 | Tailscale | 个人使用零运维，自带穿透与中继 | 自建 rendezvous+relay（后续可选） |

## 5. 非功能
- 性能目标：见 INDEX.md 成功指标；Agent CPU < 15%（硬编 1080p60）。
- 日志：`tracing`，Agent 写 `%LOCALAPPDATA%\rd\logs\`，按天滚动保留 7 天；不记录按键内容。
- 监控：控制端 HUD 显示 fps / RTT / 码率 / 编码器 / 渲染级别。
