# 协议契约（rd.proto v0）
- 状态：已确认
- 补充：终端流为 QUIC 双向流；`OpenWindowAck.video_stream_id`/`TerminalOpened.stream_id` 填 QUIC stream id，控制端视频/瓦片按帧头 `window_id` 路由（见 T-004、T-019）。

## 摘要
QUIC 单连接，ALPN `rd/0`。流 0 为双向控制流（长度前缀 protobuf）；每个窗口视频、瓦片、终端各开单向/双向流；输入走 QUIC datagram（鼠标移动）+ 控制流（点击/按键，需可靠）。

## 1. 连接与鉴权
- 双方各持自签 Ed25519 证书；TLS 双向认证，**应用层校验对端证书 SHA-256 指纹在信任列表中**。
- 未信任时只允许 `PairRequest`：控制端提交被控端托盘显示的 6 位配对码；Agent 用 SPAKE2 验证码并交换指纹，成功后双方写入信任列表。
- 端口：Agent 监听 `0.0.0.0:21118/udp`（[假设]，可配）；推荐防火墙仅允许 Tailscale 网卡（`100.64.0.0/10`）。

## 2. 控制流消息（stream 0）
```proto
syntax = "proto3"; package rd.v0;

message Envelope { uint32 req_id = 1; oneof msg {
  Hello hello = 2; HelloAck hello_ack = 3;
  PairRequest pair_req = 4; PairResult pair_res = 5;
  ListWindows list_windows = 10; WindowList window_list = 11; WindowEvent window_event = 12;
  OpenWindow open_window = 13; OpenWindowAck open_window_ack = 14; CloseWindow close_window = 15;
  ViewportInfo viewport = 16; KeyEvent key = 20; MouseButton mouse_btn = 21; MouseWheel wheel = 22; TextInput text = 23;
  OpenTerminal open_term = 30; TerminalOpened term_opened = 31; TerminalResize term_resize = 32;
  StatsReport stats = 40; Error error = 99; } }

message Hello { uint32 proto_ver = 1; string device_name = 2; repeated Codec decode_caps = 3; bool supports_444 = 4; }
message HelloAck { uint32 proto_ver = 1; string host_name = 2; repeated Codec encode_caps = 3; }
message PairRequest { bytes spake2_msg = 1; }  message PairResult { bool ok = 1; bytes spake2_msg = 2; string reason = 3; }

message WindowInfo { uint64 id = 1; string title = 2; string process = 3; uint32 pid = 4; bytes icon_png = 5;
  int32 x = 6; int32 y = 7; uint32 w = 8; uint32 h = 9; uint32 dpi = 10; bool resizable = 11; bool minimized = 12; }
message ListWindows {}  message WindowList { repeated WindowInfo windows = 1; }
message WindowEvent { enum Kind { CREATED=0; DESTROYED=1; MOVED=2; TITLE=3; CHILD_ADDED=4; CHILD_REMOVED=5; } Kind kind = 1; WindowInfo info = 2; uint64 root_id = 3; }

enum FitMode { FIT = 0; SCALE = 1; NATIVE = 2; }
enum RenderLevel { L0_PIXEL = 0; L1_HYBRID = 1; L2_SEMANTIC = 2; }
message OpenWindow { uint64 window_id = 1; FitMode fit = 2; RenderLevel max_level = 3; uint32 max_fps = 4; }
message OpenWindowAck { uint64 window_id = 1; RenderLevel level = 2; uint32 video_stream_id = 3; uint32 tile_stream_id = 4; Codec codec = 5; uint32 w = 6; uint32 h = 7; }
message ViewportInfo { uint64 window_id = 1; uint32 css_w = 2; uint32 css_h = 3; float dpr = 4; }

message KeyEvent { uint32 scancode = 1; bool extended = 2; bool down = 3; uint32 modifiers = 4; }
message MouseButton { uint64 window_id = 1; int32 x = 2; int32 y = 3; uint32 button = 4; bool down = 5; }
message MouseWheel { uint64 window_id = 1; int32 x = 2; int32 y = 3; int32 dx = 4; int32 dy = 5; }
message TextInput { string text = 1; }

message OpenTerminal { string shell = 1; uint32 cols = 2; uint32 rows = 3; string resume_id = 4; }
message TerminalOpened { string term_id = 1; uint32 stream_id = 2; }
message TerminalResize { string term_id = 1; uint32 cols = 2; uint32 rows = 3; }

enum Codec { H264_420 = 0; H264_444 = 1; HEVC_444 = 2; AV1 = 3; }
message StatsReport { uint32 fps = 1; uint32 rtt_ms = 2; uint32 kbps = 3; uint32 decode_ms = 4; }
message Error { uint32 code = 1; string message = 2; }
```

## 3. 数据流帧格式
| 流 | 方向 | 帧头（小端） | 负载 |
|---|---|---|---|
| 视频 | Agent→控制端 单向 | `u64 window_id, u32 seq, u64 pts_us, u8 flags(bit0=key), u32 len` | H.264 Annex-B AU |
| 瓦片 | Agent→控制端 单向 | `u64 window_id, u32 frame_seq, u16 x,y,w,h, u8 fmt(0=QOI,1=zstd-BGRA), u32 len` | 瓦片数据；`fmt=255` 表示失效清除 |
| 终端 | 双向 | `u32 len` | 原始 VT 字节（Agent→）/ 输入字节（→Agent） |
| 鼠标移动 | 控制端→Agent datagram | `u8 type=1, u64 window_id, i32 x, i32 y, u32 seq` | — |

## 4. 错误码
| code | 含义 |
|---|---|
| 1 | 未鉴权 | 
| 2 | 配对码错误/过期 |
| 10 | 窗口不存在 |
| 11 | 窗口无法捕获（最小化/受保护） |
| 12 | 无法调整尺寸（已退化为 SCALE） |
| 30 | 终端启动失败 |
| 40 | 输入被 UIPI 拦截（前台窗口以管理员权限运行；Agent 30s 去抖一次性提示，D-013 包2） |

## 5. v0 实现语义澄清与 v0.1 变更候选（M1 联调确认，2026-10-15）

以下为 M1 实现中确认的语义约定（v0 已按此实现）与发现的协议缺口（v0.1 候选，改协议前两端口径以此节为准）。

### 5.1 语义澄清（v0 已实现，双方按此对齐）
1. **未信任连接的 Hello 回 `Error{1}`**：控制端握手为 RPC（等响应）语义，Agent 对未信任连接的 Hello 必须回 `Error{1}`（沿请求 req_id），控制端以此触发配对流程；配对成功后 Agent 发 `HelloAck`（配对成功推送 req_id=0，正式 ACK 走重连后的握手）。
2. **`CloseWindow` / `ViewportInfo` 无应答**：Agent 静默处理（关闭幂等），控制端**禁用 rpc**，走 req_id=0 单向发送。
3. **`TerminalOpened` 先于终端快照**：快照可达 1 MiB，若对端等回包才开始读流会被 QUIC 流控窗口（~64 KiB）阻塞死锁；控制端按 `stream_id` 注册路由（conn 侧 2 s TTL 缓存兜底时序）。
4. **datagram/控制流 `window_id` 均为 hwnd 的十进制数值**；控制端 DTO 中为十进制字符串（JS 安全整数考虑），发送前解析回 u64。
5. **瓦片 `frame_seq` 与产生它的视频帧 `seq` 对齐**；视频 `seq` 为编码帧序（非发送序）。

### 5.2 v0.1 变更候选（当前以实现侧补偿，未改协议）
1. `TerminalExit { term_id, string code }`：终端进程退出通知（当前控制端以存活探测/写失败推断，退出码丢弃）。
2. `TermClose { term_id }`：控制端关闭终端标签时通知 Agent 停止推送（当前残留带宽至连接断开）。
3. （可选）`StatsReport` 增加 `window_id`：多标签时错误/统计可按窗口路由（当前设备级广播）。

## 7. v0.2 已落地变更（T-027/T-028/T-031，2026-10-24 ~ 10-31；向后兼容：新 oneof tag + 新字段）

### 7.1 新消息（文件传输，T-031）
| 消息 | tag | 方向 | 语义 |
|---|---|---|---|
| `FileListReq { string path }` / `FileListAck { repeated FileEntry entries, string path }` | 45/46 | 控制端↔Agent | RPC 列目录。path 为绝对路径，空 = 被控端主目录；失败回 `Error{55}`。条目目录在前、名称不分大小写排序 |
| `FileXferOffer { uint64 xfer_id, string name, uint64 size, bool pull, string remote_path }` | 47 | 控制端→Agent | 传输握手（req_id=0）。`pull=false` 推送：name=纯文件名，Agent 消毒后写 `Downloads\rd接收`（重名 `(n)` 去重），收齐 eof 分片后回 `FileXferAck`，校验失败立即回 ok=false；`pull=true` 拉取：remote_path=被控端绝对路径，Agent 后台任务顺序发 `FileXferChunk`，发完即止无 Ack，路径无效发 `FileCancel` |
| `FileXferChunk { uint64 xfer_id, uint32 seq, bytes data, bool eof }` | 48 | 双向 | 顺序分片（QUIC 可靠流保序），64KiB，eof=true 收尾。全部 req_id=0，按 xfer_id 路由 |
| `FileXferAck { uint64 xfer_id, bool ok, string message }` | 49 | Agent→控制端 | 推送完成回执（req_id=0）；message=落盘路径或大白话失败原因 |
| `FileCancel { uint64 xfer_id, string reason }` | 50 | 双向 | 取消（接收方校验/写失败/用户取消）；接收侧丢弃半成品 |

安全与审计：接收目录固定 + 文件名消毒（防穿越/非法字符/Windows 保留名）；列目录与终端同级（会话本有任意文件能力）不设白名单；每次传输完成落审计（`file_send_done`/`file_recv_done`，只记名字与字节数）。已知限制：推送分片在被控端分发循环内落盘，千兆局域网大文件传输期间控制流其他消息延迟上升（与 RustDesk 一致，v0.3 拆独立流）。
